# Index (Research Notes)

- **PDF start page:** 387
- **Status:** Source-verified

## Purpose

The PDF's index runs **pp. 387-398**. It is a page-number lookup, not a topic narrative. This file turns the
entries the project actually uses into a compact "where do I look?" table, so a question can be routed to a
page range before opening the PDF. It is not a reproduction of the full index.

## How the index is organized

- Alphabetical by term, with sub-entries indented under the main term.
- Page numbers are **printed HIG pages**, which match PDF page numbers 1:1 in this file (p. 1 = PDF page 1).
- Keyboard shortcuts have a double role: the shortcut itself is indexed (e.g. `Command-S 180, 372`) and the
  full table is in Appendix A (pp. 367-374). The index often cites both the prose page and the appendix page.
- `See` entries redirect synonyms (e.g. "tooltips. See help tags", "cursors. See pointers",
  "disabled items. See dimmed items").
- Some terms point to a chapter range plus a specific sub-page (e.g. "sliders 305, 309").

## Index quirks worth knowing

- The index mixes **concept pages** and **appendix pages** for shortcuts; a shortcut lookup usually needs both
  the command's own page and pp. 367-374.
- Cross-references are common and are not reciprocal. "spinning wait cursor" points to p. 163, but the entry
  "asynchronous progress indicator" points to p. 314; they are different things (pointer vs. progress control).
- "sheet" is indexed under "sheets (document-modal dialogs) 236-237"; the `document-modal dialog` entry adds
  the definition and the all-sheets rule on p. 377 (glossary).
- "dimmed items" is where disabled-menu/interface guidance is filed; "unavailable items. See dimmed items".
- "tooltips. See help tags" and "cursors. See pointers" are useful because chapter text uses the older terms.
- Page ranges are inclusive and sometimes point at a figure rather than prose (e.g. icon perspective figures
  on pp. 145-146).
